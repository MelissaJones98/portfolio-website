The Witch's Book Nook - Book Club Website

Description

As part of a Codecademy course I was tasked to create a website for a club, I chose to create a website for a fictional book club, showcasing skills in responsive web design. The club, its members and its meet ups are all made up.


Features

The website contains five pages:

  • Home: greets the user and introduces the book club
  • About Us: a brief history of the club's creation and details of the founder
  • Books: the upcoming book and 16 past books, with cover art, descriptions and club ratings for the past books
  • Meet Ups: a schedule of club meetings, plus the meeting address and a map
  • Join Us: a sign up form for people to become members of the book club

The Join Us form is front-end only. It has no back end, so submitted details are not saved or sent anywhere.


Responsive Design

The layout is built with CSS media queries, using no CSS frameworks:

Layout Screen Width Stylesheet
Mobile 320px to 425px mobile.css
Tablet 426px to 1023px tablet.css
Desktop 1024px and above desktop.css

desktop.css also has extra adjustments for larger screens from 1440px. general.css holds styles shared across layouts, including the form styling used by both tablet and desktop.

  • CSS

Reddit Clone

As this project is designed entirely to be a learning/portfolio project I have decided to go an alternative route to complete this project and make it fully functional. After carrying out some research I decided to create my own databases and build a real full-stack app. This means my forms will need to do genuine authentication.


Features

  • Users can access your application at a URL
  • Users see an initial view of the data when first visiting the app

  • Users can filter the data based on categories that are predefined
  • Users are shown a detailed view (modal or new page/route) when they select an item

Securing Acme Bank

Description

A Codecademy project to find and fix security vulnerabilities in Acme Bank, a deliberately insecure Node.js/Express banking app. Users can log in, transfer money, download their records, view a public ledger and post on a public forum. The original app (app.js) was open to cross-site scripting (XSS), SQL injection, cross-site request forgery (CSRF) and session theft. This project secured it across six tickets, each tested by attacking the running app before and after the fix.
